# 0.2.1

发布时间：2026-10-21

## 这一版解决什么

0.2.0 的两个发布版问题都能追溯到同一处：**交付的可执行文件带着低完整性标签**。

1. **托盘没有图标**。程序进程在，但右下角看不到图标。原因是进程以低完整性级别启动，`Shell_NotifyIcon` 向资源管理器注册图标时被 UIPI 拒绝，返回 `ERROR_ACCESS_DENIED (5)`；WinForms 的 `NotifyIcon` 会静默吞掉这个失败，于是只剩一个「看不见的托盘程序」。
2. **自包含单文件版启动即退出**。同一原因导致无法创建 `%TEMP%\.net` 解压目录，宿主返回 `0x800080A0` / `0x8000809F`。

修复方式是把发布产物的完整性标签显式设为 `High`。标签只是「上限」，进程最终级别仍取启动者级别，因此在普通用户会话里行为和未打标签完全相同。

## 发布形态

| 文件 | 体积 | 常驻内存（实测） | 说明 |
| --- | --- | --- | --- |
| `FaderDeck-0.2.1-win-x64.exe` | 0.5 MB | 约 131 MB 工作集 / 64 MB 私有 | 需 .NET 8 Desktop Runtime，推荐 |
| `FaderDeck-0.2.1-win-x64-standalone.exe` | 63 MB | 约 245 MB 工作集 / 130 MB 私有 | 自包含，无需运行时 |

自包含单文件比 thin 版多占约 110 MB 内存，因为整套 .NET + WPF 程序集都在 bundle 里，运行时必须留在进程内存。若机器已装 .NET 8 Desktop Runtime，用 thin 版即可。

## 自查与修复

```powershell
icacls .\FaderDeck-0.2.1-win-x64.exe
icacls .\FaderDeck-0.2.1-win-x64.exe /setintegritylevel High
```

`icacls` 输出里若看到 `Mandatory Label\Low Mandatory Level`，就是本文说的那种情况；设置成 `High`（或复制到普通目录重新生成）后重启程序即可。

## 功能

功能与 0.2.0 相同：主播模式页（模式切换、直播 / 监听两套混音、入混音开关、监听开关、硬件输出）、设备卡片（个人合成器 / 麦克风输入）、EQ 切换后自动刷新 GG 显示。
