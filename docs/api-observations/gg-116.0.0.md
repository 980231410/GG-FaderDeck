# GG 116.0.0 Sonar 本地接口观察

> 本文档记录的是对**公开分发的第三方软件**在本地运行时行为的观察结果（HTTP 接口的形状），
> 属于事实性信息，不包含该软件的源代码或资源。相关商标归其所有者，本项目与其无关联。

验证日期：2026-08-01（Streamer 模式于 2026-10-20 补充）  
验证方式：只读取状态，写操作仅写回原值或原目标设备。

## 服务发现

- Sonar 作为独立的 `SteelSeriesSonar.exe` 进程运行。
- 端口不可硬编码。
- 当前 Windows 环境访问 GG 加密 `/subApps` 端点时发生 SChannel 凭据错误，因此实现同时支持 Windows TCP owner table 发现策略。
- TCP 策略只检查 `SteelSeriesSonar` 所属的 loopback listener，并以 `GET /mode` 返回 `classic` 或 `stream` 作为二次确认。

| 请求 | 用途 | 结果 |
|---|---|---|
| `GET /mode` | 当前 Sonar 模式 | 200 |
| `GET /volumeSettings/classic` | 通道音量与静音 | 200 |
| `GET /audioDevices` | 物理/虚拟输入输出设备 | 200 |
| `GET /classicRedirections` | 通道物理设备绑定 | 200 |
| `GET /AudioDeviceRouting` | 应用音频会话和所在端点 | 200 |

## 实时事件

- WebSocket 地址与 HTTP 服务使用相同的动态 loopback 端口：`ws://127.0.0.1:<port>/sock`；
- 音量和静音变化通过 `SONAR_EVENT_VOLUME_DATA` 推送；
- `data.masters.classic` 表示 Master，`data.devices.<channel>.classic` 表示各 Sonar 通道；
- 事件是增量数据，可能只含 `volume`、`muted` 或单个通道，客户端必须合并到已有状态；
- 外部客户端调用 Classic 音量 HTTP PUT 会改变 Sonar 状态，但实测不会广播音量事件；GG 自己调用 PUT 时依靠前端 Redux 同步更新，因此外部 HTTP 写入不会及时刷新已经打开的 GG 页面；
- 通过对应 Sonar Windows 虚拟端点的 `IAudioEndpointVolume` 修改音量或静音，会被 Sonar 识别并广播，与键盘媒体键使用相同的同步链路；
- Game、Chat、Media、Aux 使用虚拟 render 端点，Mic 使用虚拟 capture 端点；Master 没有独立的 Windows 端点，仍需使用 HTTP；
- WebSocket 不可用时可继续使用 `GET /volumeSettings/classic` 进行低频降级同步。

## Streamer 模式（2026-10-20 补充验证）

Streamer 模式是 Sonar 的第二套混音；经典模式与主播模式的音量分别存放在不同分支下：
`/volumeSettings/classic` 只含 `classic` 分支，`/volumeSettings/streamer` 的每个通道同时含 `streaming` 与 `monitoring` 两条子分支。

| 请求 | 用途 | 结果 |
|---|---|---|
| `GET /mode` | 当前模式，`classic` 或 `stream` | 200 |
| `PUT /mode/{classic\|stream}` | 切换 Sonar 混音模式 | 200，回读一致 |
| `GET /volumeSettings/streamer` | 主播混音音量，`masters` 与 `devices.<channel>` 下含 `stream.{streaming,monitoring}` 与 `classic` | 200 |
| `PUT /volumeSettings/streamer/{mix}/{channel}/volume/{0..1}` | 设置主播混音音量，`mix` 为 `streaming` 或 `monitoring` | 200，回读一致 |
| `PUT /volumeSettings/streamer/{mix}/{channel}/isMuted/{bool}` | 设置主播混音静音 | 200，回读一致 |
| `GET /streamRedirections` | 三条虚拟输出：`streaming`、`monitoring`、`mic`，含 `deviceId`、`status[{role,isEnabled}]`、`isRunning` | 200 |
| `PUT /streamRedirections/{mix}/redirections/{role}/isEnabled/{bool}` | 控制某个通道是否进入该混音 | 200，回读一致 |
| `GET /streamRedirections/isStreamMonitoringEnabled` | 监听混音开关 | 200 |
| `GET /streamRedirections/isStreamMonitoringLocked` | 监听开关是否被锁定 | 200 |
| `PUT /streamRedirections/isStreamMonitoringEnabled/{bool}` | 切换监听混音 | 200，回读一致 |
| `GET /deviceOut` | `selectedDeviceOut` 与 `deviceOutSettings[{feature,volume,mute}]` | 200 |
| `GET /deviceOut/audioPath` | 当前生效的硬件输出特性 | 200 |
| `GET /deviceOut/volume/{feature}`、`GET /deviceOut/mute/{feature}` | 单个硬件输出特性状态 | 200 |
| `PUT /deviceOut/volume/{feature}/{0..1}`、`PUT /deviceOut/mute/{feature}/{bool}` | 硬件输出音量与静音 | 200，回读一致 |
| `PUT /deviceOut/audioPath/{feature}` | 切换硬件输出路径 | 200 |
| `PUT /streamRedirections/{streaming\|monitoring\|mic}/deviceId/{escapedDeviceId}` | 切换主播混音输出设备 / 麦克风输入设备 | 200，返回该条重定向（含 `deviceId`、`status`、`isRunning`） |

补充说明：

- 完整路由、结构与逆向来源见 [streamer-mode.md](streamer-mode.md)；
- `{channel}` 取值与经典模式一致：`master`、`game`、`chatRender`、`chatCapture`、`media`、`aux`；`{mix}` 取值为 `streaming`、`monitoring`；
- 主播混音的通道成员关系不写在 `/volumeSettings/streamer` 里，而是由 `/streamRedirections` 的 `status[].isEnabled` 表达，二者需合并使用；
- 主播混音音量**没有** WebSocket 事件推送（`SONAR_EVENT_VOLUME_DATA` 只覆盖经典分支），客户端使用低频轮询并在写入后立即回读；
- 模式切换会让 GG 重新配置虚拟输出设备，切换后等待约 400ms 再读取状态更稳定；
- 本机未探测到 `PUT /deviceOut/selectedDeviceOut/{feature}`（404），`GET /features` 返回空数组，两者暂不依赖；
- GG 的 Sonar 页面把三条重定向设备分别标注为「个人合成器」（`monitoring`）、「流式处理器」（`streaming`）、「麦克风输入」（`mic`）；`mic` 这条没有 `status` 成员关系，只有 `deviceId`。

## EQ 选中态不会通过事件广播（2026-10-20 补充验证）

- `PUT /configs/{id}/select` 会真实改变 Sonar 的选中预设，`GET /configs/selected` 立刻反映新值；
- 但同一个 Sonar `/sock` 连接在切换后**收不到任何**「选中预设变更」事件：抓包只看到 `SONAR_EVENT_AUDIO_SESSION_OPENED_DATA` / `SONAR_EVENT_AUDIO_SESSION_CLOSED_DATA`，即使用户在 GG 界面里手动切换 EQ 也一样；
- 结论：GG 的 Sonar 页面只在自身发起切换时更新选中预设显示，外部写入无法通过事件驱动它重绘；
- 因此 FaderDeck 在 EQ 写入成功后主动重新载入 GG 窗口（Ctrl+R）来同步显示，重载会让 GG 回到 Sonar 主页并有一次可见闪动，属于已知取舍。

## 安全约束

- 客户端拒绝非 loopback Sonar 地址。
- 不关闭全局 TLS 校验。
- 不记录设备 GUID、进程完整路径或音频会话 ID。
- 未验证的 GG 版本后续应经过能力探测，再开放写操作。
